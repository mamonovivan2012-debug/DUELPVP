# ARENA DUEL — Visual Overhaul & Bugfixes

Проект сохранён на Godot 4.3+ и развивается поверх исходной игры: сохранены исходная арена, пять персонажей, базовая боевая система и индивидуальные способности.

## Что изменено в Visual Overhaul

- Заменены все пять игровых портретных спрайтов на новые детализированные полнофигурные изображения 512×640 с прозрачностью: Рыцарь, Разбойник, Друид, Страж и Тёмный принц.
- Игровые бойцы теперь рисуются крупнее, с динамической тенью под ногами, мягким дыханием/покачиванием в idle, более заметным движением и небольшим рывком при атаке.
- Тёмный принц получил отдельный дымчатый силуэт, фиолетовую ауру, след и сохранённые восемь анимированных щупалец.
- Удалены старые простые 192×192 пиксельные фигурки из игрового рендера; новые изображения используются также в портретах HUD.

## Исправления логики

- Эффект обездвиживания от корней теперь блокирует движение первого игрока, второго игрока и бота, а не только часть локального управления.
- Таймеры теневого следа теперь независимы для двух бойцов; раньше один общий таймер мог сбивать частоту эффекта.
- При запуске нового боя полосы здоровья снова получают максимум 100 HP, чтобы повышенное здоровье босса из прошлой главы не оставалось в PvP/PvB.
- Сообщение о победе/поражении в кампании больше не перезаписывается обычным сообщением на следующем кадре.
- Добавлен статический валидатор путей ресурсов, структуры файлов и размеров спрайтов: `python tools/validate_project.py`.

## Сохранённые функции и режимы

- Переработано главное меню: центрированная панель, fantasy-оформление, силуэт разрушенной крепости, пыль и атмосферное затемнение.
- Переработан боевой HUD: имена бойцов, полосы здоровья, таймер и отдельные индикаторы перезарядки способностей.
- Исправлено назначение геймпадов: первый подключённый контроллер управляет P1 и в PvB; второй — P2 в локальном PvP. Если подключён один контроллер в локальном PvP, второй игрок остаётся на клавиатуре.
- Левый стик управляет движением; A — атакой; X — способностью.
- Атаки и способности обрабатываются по фронту нажатия, удержание кнопки не повторяет действие каждый кадр.
- Добавлены экран настроек громкости и отображение схемы управления/подключённых контроллеров.
- Добавлена сюжетная кампания из пяти глав с отдельным героем каждой главы, сюжетными вступлениями, боссами на базе сохранённого боевого ИИ и постепенным открытием глав.
- Прогресс кампании и уровни громкости сохраняются в `user://arena_duel_progress.cfg`.
- Добавлены оригинально синтезированные музыкальные темы меню и боя, а также эффекты меча, попадания, тёмной способности и интерфейса.
- Добавлены атмосферные факельные ореолы, частицы пыли, анимированные щупальца и тёмный след Тёмного принца.
- Сохранены параметры «Владений бездны»: 10 секунд действия, 30 секунд перезарядки, восемь теневых щупалец и усиление принца на 30% в пределах территории.
- Workflow GitHub Actions собирает Windows EXE с встраиваемым PCK.

## Управление

| Игрок | Движение | Атака | Способность |
|---|---|---|---|
| P1 | WASD | Пробел | Q |
| P2 | Стрелки | Enter | Shift |
| Геймпад | Левый стик | A | X |

Назначение устройств: первый геймпад — P1, второй — P2. В PvB первый геймпад всегда управляет игроком, а бот остаётся противником.

## Запуск

1. Установи Godot 4.3 или новее.
2. Открой `project.godot` через Project Manager.
3. Нажми F6 для запуска текущей сцены или F5 для запуска проекта.

## Windows EXE через GitHub Actions

1. Загрузи проект в GitHub-репозиторий.
2. Открой вкладку **Actions** и запусти workflow **Build Windows EXE** (или создай тег вида `v1.0`).
3. Скачай артефакт `ArenaDuel-Windows`.
4. В экспортном пресете включено встраивание PCK, поэтому игровые ресурсы упаковываются внутрь EXE.

## Что ещё не реализовано полностью

- Кампания сейчас представляет собой пять сюжетных глав с текстовыми вступлениями и боями с усиленными противниками. Полноценные исследовательские уровни, интерактивные квесты, постановочные кат-сцены и уникальные скриптовые боссы требуют отдельной разработки.
- Онлайн-режим оставлен исходным ранним ENet-прототипом. Полная синхронизация атак, способностей, выбора героев и состояния матча не реализована.
- Персонажи по-прежнему представлены 2D-спрайтами (теперь детализированными и полнофигурными). Полноценные 3D-модели, скелетные анимации и 3D-арены не добавлены.
- Звуковые эффекты и музыка синтезированы специально для проекта, но индивидуальных музыкальных тем и озвучки каждого героя пока нет.
- Статический валидатор проекта пройден. Но Godot executable недоступен в среде подготовки, поэтому проверка импорта/парсинга самим движком, запуск сцен, физическое тестирование контроллеров и фактический экспорт Windows не подтверждены. Workflow GitHub Actions выполняет headless-импорт, smoke test и экспорт на GitHub runner.

## Структура

- `project.godot` — настройки проекта.
- `scenes/main.tscn` — главная сцена.
- `scripts/main.gd` — логика меню, управления, боёв и кампании.
- `assets/` — арена, новые полнофигурные спрайты бойцов и звуковые ресурсы.
- `tools/validate_project.py` — статическая проверка целостности ссылок и игровых спрайтов.
- `.github/workflows/build-windows.yml` — автоматическая сборка Windows.
